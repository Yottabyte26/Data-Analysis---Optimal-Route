Q02｜最少中转 ≠ 最短旅行时间（基础）
一句话记住：先把「最优」的口径写清楚，再谈算法。

工程背景。要给出行用户推荐机场到机场的路线。业务方一会儿说「中转越少越好」，一会儿说「总耗时越短越好」，还有人说「航程最短才省油」。三种口径在同一张航线图上给出的答案并不一致。评测日期为 2026-01-15，季节性航线只有在运营窗口内才算可用。

数据与约束。Q02_airports.csv（620 个机场，含已关闭）、Q02_routes.csv（7355 行）、Q02_ground_links.csv（30 条地面接驳，也应视作边）、Q02_od_pairs.csv（200 对起终点）。

任务。

l 必做 A｜清洗与探查：统计重复行、共享航班行、非当季航线、指向关闭或不存在机场的行、孤立机场；说明每类你怎么处理、不处理会怎样。给出清洗前后可用于建图的边数。

l 必做 B｜三套口径：分别求「最少中转（BFS）」「最短总耗时（Dijkstra）」「最短总里程（Dijkstra）」下的路径，对 200 对 OD 给出三种结果不一致的比例，并挑 3 对逐条列出路径与差距。

l 必做 C｜口径冲突：找出「按最少中转选出来的路线，耗时超过按最短耗时路线两倍」的具体 OD 对，解释根因（提示：先看看地面接驳边的 stops 字段）。给出你会向业务方推荐哪套口径、理由与代价。

l 进阶 D｜规模与预处理：若 OD 查询量从 200 涨到 2 万，是否值得预计算全源最短路或连通分量？给出预处理时间、单次查询时间、内存三项对比。

l 进阶 E｜约束变化：只允许某一家航司联盟的航班、或禁止任何地面接驳时，结论怎么变？给出切换条件。

提交物：清洗前后统计表、三口径结果对照表、至少 3 条逐段路径、200 对 OD 的差距分布图。
