以上筛查线是本次审计设定的宽松排查阈值，用于定位明显矛盾，线内记录仍需验证是否存在实际交通服务。共 28/30 条超线。最突出的是 A0009 → A0465（bus），269 分钟内要覆盖至少 13796.68 km，隐含平均速度 3077.33 km/h。

1. **坐标本身有误**。未发现缺失或越界。坐标在合法范围内仍可能与机场实际位置不符。由于缺少坐标真值或数据字典，现实地理准确性待确认。
2. **ID 映射错误**。原表主键唯一，独立连接与现有字典查找计算一致。现有文件中未发现机场 ID 查错行或程序把经纬度用反的证据。
3. **接驳原始边连接了远端机场**。逐字段对照表明，清洗保留了原表的起终点、交通方式和耗时。远距离与较短耗时的组合已经存在于原始记录中。按距离大小删边会改变题目输入，审计保留全部记录。
4. **模拟或非真实地理关系**。规则化城市和国家标签、原表中大量远距离接驳与隐含速度冲突，共同支持模拟数据的解释。缺少生成规则和数据字典，仍无法确认接驳耗时、端点是如何生成的。

作为内部交叉核查，清洗航线表 5,191 条中有 5,191 条的原始里程与同一坐标表的大圆距离相差至多 0.1 km，差值绝对值的中位数为 0.025 km。这衡量航线与坐标的内部一致性，无法验证坐标的现实地理准确性。

## 能否继续使用 Haversine 与最短总里程影响

Haversine 可以继续用于复现机场间的大圆距离。若作业明确允许地面边采用球面代理里程，可继续把它作为非负边权，并说明结果是航线里程与地面球面距离之和。若目标是实际门到门交通里程，现有字段不足以确定地面边真实距离。

现有代码对航线使用表内 `distance_km`，对地面接驳使用大圆距离。当前有 0 个同向机场对同时出现在清洗航空和地面边表中。代理距离会参与所有候选路径累加和比较，高估或低估地面边权都可能改变最短路径，尤其是混合航空与地面的路径。对于真实地面行程，大圆距离通常低估沿线路行驶的距离。对模拟数据，真实边权缺失，无法确定代理值与题目预期之间的偏差方向。接驳耗时不参与最短里程目标，异常速度也不会触发 Dijkstra 的非负权重检查。本次只审计输入及权重计算。

##地面接驳距离异常处理：##

数据审计发现，原始地面接驳数据未提供实际线路里程。通过机场经纬度和 Haversine 公式计算两端大圆距离后，发现30条接驳记录中有28条超过设定的交通速度筛查阈值，表明部分接驳关系与机场地理位置存在明显不一致。

进一步检查发现，机场坐标不存在缺失或越界，机场 ID 与坐标的关联正确，独立计算结果与程序计算结果一致。因此，未发现距离计算公式或坐标映射程序存在错误。

考虑到缺少真实地面交通里程及数据生成规则，本实验不擅自删除或修改原始接驳记录，而是保留全部地面接驳边，并使用 Haversine 大圆距离作为代理权重。需要说明的是，该距离不代表真实公交、铁路或渡轮的实际行驶里程，可能对最短总里程路径产生影响。
